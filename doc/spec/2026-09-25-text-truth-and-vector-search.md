# Spec: 文本真值回显 + 向量语义检索

> 关键词：grep 回显 文本真值 找不到当不存在 渐进披露 语义检索 semantic_search 空壳
> 向量 嵌入 embedding ONNX ort bge 余弦相似 本地模型 离线

- 状态：**已批准实施**
- 日期：2026-09-25
- 范围：① 符号类工具默认带上「文本真值」 ② `semantic_search` 从空壳改为真正的向量检索

---

## 一、问题

### 1.1 三次事故的共同致命点：**「漏了却装成『没有』」**

| 次 | 缺口 | 那个 0 被读成 | 真值 |
|---|---|---|---|
| 1 | 索引过期 | 「这个类方法不存在」 | 存在，只是没索引 |
| 2 | 限定名 `Class::method()` 不建边 | 「没有调用方，改签名很安全」 | 有（TS 7 处 / C++ 203 处） |
| 3 | 枚举量不索引 | 「没人用这个枚举，加一项很安全」 | 15 处；**漏改定长表 ⇒ SIGSEGV** |

补全索引覆盖（另一份 spec）是**治本之一**，但**永远补不完** ——
只要还有任何一类没索引，同样的 0 还会再来。

**本条是正面解**：让工具自己把**文本真值**摆出来，与符号索引结果**并列**。

### 1.2 `semantic_search` 是空壳（实测）

`crates/mcp/src/tools.rs:1186`：

```rust
let results = match query_engine.search_by_name(&params.description, None, None, limit) {
```

**调的是按名字的词法搜索**，与 `search_symbol` 同一条路径，**没有任何语义成分**。
名字叫「语义搜索」、行为是关键词匹配 —— **这本身是第四次静默误导**。

## 二、设计 A：文本真值回显（渐进披露）

### 2.1 数据来源：**只扫索引已知的文件集**

**绝不做全盘 grep**（磁盘 I/O 会卡死交互，见既有纪律）。
索引里已有**已索引文件列表**，文本扫描只在这个集合内进行 —— 范围明确、可预期。

### 2.2 默认开启 + 渐进披露

| 情形 | 输出 |
|---|---|
| 符号命中 **充足**（≥ 阈值，默认 5） | 只在 meta 里附**一行汇总**：`文本另有 N 个文件 M 处出现` |
| 符号命中 **稀少或为 0** | **展开明细**：`文件:行` + 原文片段（前后裁剪到 200 字符） |

**为什么这样分**：常见符号（如 `main`）展开会回上千行、吃爆上下文；
而**真正危险的是 0 命中和稀少命中** —— 那正是「静默致错」发生的地方。

### 2.3 ★ 关键文案（治「静默致错」的就是这一句）

当**符号索引 0 命中、而文本有命中**时，响应**必须**明确写出：

> 符号索引中未找到 `X`。但**文本检索在 N 个文件、M 处找到了它** ——
> **这不代表 X 不存在**，更可能是它属于索引未覆盖的符号类别。
> 下面列出文本命中位置；**改动前请以这些位置为准**。

**不写这句，等于白做** —— 调用方（AI）看到 0 就会下「不存在」的结论。

### 2.4 输出预算

- 明细行数上限（默认 50），**超限必须告警**并给出真实总数（复用既有 `clip()` / `truncation_warning()`）。
- 单行原文裁剪到 200 字符。
- 响应总体仍受既有 `budget_tokens` / `limit` 体系约束。

### 2.5 适用范围

`search_symbol`、`find_references`，以及 CLI 的 `search` / `references`（两条路径行为一致）。

## 三、设计 B：向量语义检索（本地 ONNX，离线）

### 3.1 运行时：**复用本机已有，不下载**

实测本机已有 ONNX Runtime（Python `onnxruntime 1.28.0` 的 `capi/onnxruntime.dll`）。
Rust 侧用 **`ort` 2.0.0-rc.13**（正是封 ONNX Runtime 1.28，版本对得上），
通过 `ORT_DYLIB_PATH` 指向本机 DLL，**避免构建期下载运行时**。

### 3.2 模型：**需要下载**（唯一新增的外部产物）

- 选型：小型多语言/中文友好的句向量模型（如 `bge-small-zh-v1.5`，约 95 MB）。
- **下载前必须先告知用户**：模型名、体积、**落盘绝对路径**（项目纪律 3.4）。
- **落盘位置（2026-09-25 用户裁定）**：**用户级数据目录**
  `C:\Users\Administrator\.codeconnect\models\`
  —— 即工具自己的用户级数据目录（全局配置 `~/.codeconnect/config.toml` 已在同一层）。
  **所有项目共用一份，只下载一次**；用户明确否掉了「放到 `E:\gongju\` 这类软件目录」与
  「每个项目的 `.codeconnect/models/` 各存一份」两个方案。
- 查找顺序：用户级目录 → 找不到则**明确报错并给出获取方式**（见 §3.2 末）。
- **模型缺失时**：`semantic_search` 必须**明确报错说明缺少模型与获取方式**，
  **绝不能**退回 `search_by_name` 假装成功（那正是现在的病）。

### 3.3 嵌什么

- **符号名 + 签名**（必要时加 doc 注释首行）。
- **不嵌函数体** —— 体积与收益不成比例；函数体的语义检索是另一个议题。

### 3.4 存储与查询

- 向量与 id 映射落 `<data_dir>/embeddings.bin`（f32，简单二进制格式 + 头）。
- 查询：查询串嵌入 → 余弦相似 → top-K（符号量级几千，**暴力扫描足够**，先不引入 ANN 索引）。
- 增量：新增/变更符号重新嵌入；删除符号同步清理。

### 3.5 `semantic_search` 重写

- 走真向量检索；**响应里注明检索方式**（`retrieval: "vector"` + 模型名），
  **避免再次出现「名字说语义、行为是词法」的名实不符**。
- 保留关键词检索作为**可选的对照**（如 `mode: vector | lexical | both`），默认 `vector`。

---

### 3.6 ★ 配置化（2026-09-25 用户补充，**硬性要求**）

> 用户原话：**「用户可选配置不配置向量模型，也可以指定使用模型」**

两条要求：

1. **向量模型是可选能力** —— 用户**不配置 = 该能力关闭**，工具照常用，只是没有语义检索。
2. **用户可以指定用哪个模型** —— 模型名或路径可配。

**配置形态（草案，落在 `.codeconnect.toml`）**：

```toml
[semantic]
# 不写本节 = 语义检索关闭（默认）
enabled = true
# 模型名（在用户级模型目录下查找）或绝对路径
model = "bge-small-zh-v1.5"
# 可选：覆盖模型根目录，默认 C:\Users\Administrator\.codeconnect\models\
# model_dir = "D:/models"
```

**★「未配置」必须是明确的一等状态，不能被静默掩盖**：

| 状态 | `semantic_search` 的行为 |
|---|---|
| 未配置（`[semantic]` 缺失或 `enabled = false`） | 返回**明确说明**：「未配置向量模型，语义检索不可用」+ **配置方法**。<br>**绝不**退回 `search_by_name` 假装成功 |
| 已配置但模型文件缺失 | 返回**明确错误** + 期望路径 + 获取方式 |
| 已配置且就绪 | 走真向量检索 |

**为什么这条特别强调**：现在的病**正是**「没能力却装成有能力」——
`semantic_search` 名字叫语义、实际调 `search_by_name`。
**任何形式的静默降级都会把同一个病换个地方复发。**
「没配」就直说「没配」，这是本 spec 全篇的主线（把静默变成可见），在这里同样适用。

## 五、验收标准

### A
1. 查一个**确定不被索引**的名字（如枚举量）→ 响应里**必须**出现 2.3 的那段文案 + 文本命中位置。
2. 查一个**高频词**（如 `main`）→ 只给一行汇总，**不展开**，不撑爆上下文。
3. 文本扫描**只覆盖已索引文件**（构造一个索引外文件，确认不被扫到）。
4. 明细超限时**有告警且给出真实总数**。

### B
5. `semantic_search` 用**自然语言描述**（不含符号名任何子串）能检索到相关符号 ——
   这是「真语义」与「词法」的判别性测试。
6. 模型缺失时**明确报错**，**不静默退回词法**。
7. 嵌入库与索引同步（增/改/删）。
8. `cargo test --workspace` 全绿；离线可用（断网后功能不退化）。

## 六、风险

| 风险 | 应对 |
|---|---|
| 模型下载体积/网络 | **先告知体积与路径再下**；模型缺失走明确报错分支 |
| `ort` 构建期仍可能尝试下载运行时 | 预先设 `ORT_DYLIB_PATH` 指向本机 DLL；构建失败则如实报告，不静默降级 |
| 向量检索对「标识符名」效果未必优于词法 | 验收 5 用**不含符号名子串**的自然语言查询做判别；如实报告效果，不夸大 |
| 文本扫描拖慢响应 | 只在已索引文件集内扫；给耗时上限；必要时加开关 |
| A 的默认开启会增大响应体积 | 渐进披露（充足时只一行）+ 明细上限 + 告警 |
